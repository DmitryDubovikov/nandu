# Материалы корневой папки — Ñandú Nivel 1, региональный и провинциальный этапы

Это подробная карта файлов, лежащих в корне репозитория. `CLAUDE.md` держит только правила
авторства и текущий фокус; вся археология веток — здесь.

Обе ветки **пройдены**: провинциальный тур 20 августа 2026, региональный 27 августа 2026.
Материалы остаются как справка и как фундамент национальной ветки (`national_level1/`) —
национальные пары стоят на них и ссылаются в них.

## Соглашение об именах

Файлы курса: `nandu_n1_<этап>_<тема>_<вид>.md`, где этап — `regional` / `zonal` / `provincial`,
а вид:

- `uchebnik` — учебник: теория, «ритуалы», главы с разобранными примерами (формат разборов — hard rule 8 в `CLAUDE.md`;
  в старых материалах могут ещё встречаться дореформенные таблицы «что делаем | что получается» — переводить в новый формат при правке, а не оптом).
- `reshebnik` — решебник: один блок задач на главу учебника, ответы отдельным разделом в конце.
- `roadmap` — карта корпуса + банк задач по блокам.
- `plan` / `plan_short` — подневный трекер курса.
- `tipologia` — родительский определитель типов по годам корпуса.
- `opredelitel` — боевой маршрут распознавания (самодостаточный, см. hard rule про ноль отсылок).
- `resheniya` / `klyuch` — родительские разборы и ключи.

## Региональная ветка

Последовательность курса: **СЛАУ → перевод → фигуры → счёт → боевая фаза** (работа по реальному банку).

**Корпусный вывод про приём в задаче №1** (аудит ~68 работ Nivel 1, июль 2026): вычитание двух почти-близнецов
(обычное исключение неизвестной, «вычитание уравнений») — **главный первый ход регионального №1**:
7 лет из 14 за 2012–2025, включая все пять лет 2021–2025. Отрабатывался до автоматизма.
«Сложи всё» в чистом кольцевом виде (`a+b, b+c, a+c`) в корпусе №1 Nivel 1 **не встречается ни на одном этапе** —
показан один раз как переходная идея, не отрабатывался.

### Пары
- `nandu_n1_regional_linsys_{uchebnik,reshebnik}` — системы линейных уравнений.
- `nandu_n1_regional_perevod_{uchebnik,reshebnik}` — перевод условия в систему.
- `nandu_n1_regional_figury_uchebnik` + `nandu_n1_regional_figury_klyuch` — мини-учебник по периметрам,
  решебника-близнеца нет. Ключ разбирает 14 реальных задач №2, каждая расщеплена на
  **этап 1 — перевод** (раскладка фигуры, «кирпичики», таблица «что дано | что записываем»,
  затем готовая система в врезке «✅ Результат перевода» — это и есть продукт первого прохода;
  плюс лайфхаки 1–5 и ловушка перевода этой задачи) и **этап 2 — решение** (ходы, значения,
  официальные ответы), сдвинутый вниз для необязательного второго прохода. Расщепление повторяет
  границу курса: перевод учат здесь и в `perevod`, решение систем — в `linsys`; смешивать нельзя.
  Все 14 систем решены и сверены с `nandu_problemas/historico/Regionales_N1.md` (14/14).
  Буквы у ребёнка могут отличаться от ключа — файл велит сверять смысл, а не буквы.

### Сюита «счёт» (тип 3), нумерация 1–5 по порядку первого использования
- `schet_1_atomy_uchebnik` — атомы, гл. 1–4: список/дерево, цепочка+рассадка, группа, раздача + матрица 2×2.
- `schet_2_reshebnik` — 42 задачи по маршруту в 8 блоках + диагностический диктант на 15 пунктов
  + «Запас» из 13 снятых дублей для ретро-дней.
- `schet_3_tablitsa` — «таблица умножения» атомов: шесть карточек сборки в жёсткой рамке
  «маски → что на руках → ход → формула → числа → одно и то же → не путать», самодостаточная матрица 2×2
  плюс «клетка сбоку» для перестановок с повторениями, раздел-подстраховка «Если не узнал»
  (ведущее правило: «не понимаешь — начинай выписывать», смотри на *форму* списка) и «Узнаю в лицо» —
  таблицы по `n` в порядке «что происходит | запись | число».
- `schet_3_tablitsa_sborki` — близнец предыдущего: та же рамка для восьми ходов сборки
  (миры/этапы, минус, ведущий ноль, «ровно один», раздачи с границами, сумма цифр, соседство,
  миры по особой клетке), но вместо формулы — сигнал, и **чисел для запоминания нет** (числа сборки одноразовые).
  Кончается «Сигналами в лицо» — список из 18 строк «оборот в условии → первый ход».
- `schet_4_sborka_uchebnik` — учебник сборки, гл. 5–8: этажи/миры, модификаторы, раздачи с границами,
  плитки/раскраски + боевой маршрут.
- `schet_5_opredelitel` — протокол из 4 шагов + 9 задач практикума. Ребёнок проходит их по лесенке
  «сам → подсказки → разбор»: `..._opredelitel_podskazki` — по две подсказки на задачу
  (1: разрезка/маркеры, 2: ✅-формула + диагнозы блоков, без чисел), `..._opredelitel_resheniya` — полные разборы,
  прорабатываются извлечением (прочитал целиком, закрыл, восстановил по памяти, сверил ✅-формулу и числа блоков),
  никогда переписыванием. На тур идёт только сам определитель.

Оба `schet_3_*` — **самодостаточные: ноль отсылок наружу, ни номеров дней/глав, ни клеток-указателей**;
клетка обязана нести мысль, а не адрес. Это не второй определитель — они тренируют узнавание, а не маршрут тура.
Ежедневных разминок Д2–Д8 больше нет; формат — перечитывать каждую таблицу целиком примерно раз в неделю.

- `nandu_n1_regional_schet_korpus_resheniya` — родительский ключ к банку типа 3 из роадмапа; вне нумерации 1–5.

### Роадмапы
- `nandu_n1_regional_roadmap.md` — карта корпуса + **банк задач по 8 блокам без решений** (см. hard rule 1: банк неприкосновенен).
  Ответы к реальным задачам: `nandu_problemas/historico/Regionales_N1.md`; разобранные №3 по годам —
  `nandu_n1_regional_schet_korpus_resheniya.md`; сами условия — `nandu_problemas/omn_regional/regional_<год>.md`.
- `nandu_n1_zonal_roadmap.md` — зональный этап, самостоятельный документ.

### Планы
`nandu_n1_regional_plan.md` и `plan_short` **удалены пользователем** (июль 2026). Расписание жило
в `nandu_n1_plan_2026.md` — датированный график до провинциального тура 20 августа и дальше до регионального 27 августа,
с пофайловым списком на день и флагом «Пров.» на материале, готовящем к провинциальным задачам.
После 27 августа датированного расписания нет: национальные планы тоже удалены (см. `national_level1/README.md`),
а в конце `nandu_n1_plan_2026.md` остался висячий указатель на них.

## Провинциальная ветка

Провинциальный этап стоит между зональным и региональным (в CABA называется Metropolitano).
Варианты, пропущенные годы и местонахождение ключа — в `nandu_problemas/omn_provincial/README.md`.
Провинциал — **самостоятельный финал**, а не отбор; регионал — полуфинал к национальному.

- `nandu_n1_provincial_doski_{uchebnik,reshebnik}` — закрывает провинциальный разрыв: доски с суммами,
  запреты соседства, построчные цепочки, дырки вместо фишек, миры плохих (когда вычитание считает дважды, гл. 5),
  островки на полосе (гл. 6) + три приложения (привратник-чётность, растущие узоры, ход с конца —
  последнее про задачу №1, а не про доски). Стоит на сюите «счёт» (ритуалы, «И/ИЛИ», лесенка, «минус»).
- `nandu_n1_provincial_tipologia.md` — типология по годам 2018–2025.
- `nandu_n1_provincial_trenirovka.md` (+ `_kratko`) — разминка перед боевой фазой: 12 сгенерированных
  задач-двойников (не из корпуса), по одной на каждый тип из типологии (частым типам 2–3),
  прорабатываются циклом извлечения «прочитал разбор → закрыл → воспроизвёл»; все ответы проверены независимо.
- `nandu_n1_provincial_resheniya_<год>.md` для 2018, 2019, 2022–2025 — родительские боевые ключи
  (жанра `schet_korpus_resheniya`): краткие условия без картинок, решение в порядке тура —
  №2 первым, №1 после 2 минут триажа (конкретное число → решаем; «все возможности» / доска → в конец),
  №3 пересчитан вторым способом. Ответы корпуса: `nandu_problemas/historico/Provinciales_N1.md`.
- `nandu_n1_provincial_doski_opredelitel.md` — капстоун пары, аналог `schet_5` для досок.
  Не новый материал: весь учебник досок сжат в маршрут из 4 шагов
  (шаг 0 — жанр вопроса «сколько способов / dar todas las posibilidades / возможно ли N» →
  шаг 1 — числа-или-фишки и распадается ли доска → шаг 2 — сигнал → ход →
  шаг 3 — склейка, проверки, «Explica cómo las contaste»).
  ⚠ **Самодостаточен по требованию пользователя: ноль отсылок наружу** — ни номеров глав, ни кодов ритуалов,
  ни чужих имён файлов, ни годов корпуса. Каждый из девяти ходов («Опора-сумма», «Карта соседей», «Островки»,
  «Этажи», «Дырки», «Миры плохих», «Привратник», «Растущий узор», «С конца») расписан как нумерованный план,
  исполнимый на месте, с числами; закрывающая таблица повторяет примитивы счёта (лесенка, раздача, «И»/«ИЛИ», …)
  с посчитанной арифметикой. Любая правка обязана это сохранять: указатель на главу здесь — баг.
  Несёт две развилки, которых не было в старой карте: «Карта соседей vs Островки» по числу фишек и
  «Дырки vs Миры плохих» по проверке минусом. Практикума и файлов подсказок/решений нет — эту роль играют
  `provincial_trenirovka` и реальные туры. Оба определителя открываются роутером
  («есть в задаче строки и столбцы?»); это единственная строка про доски внутри `schet_5` — счёт и доски живут в разных документах.
- `nandu_n1_provincial_pamyatka.md` — предтуровая шпаргалка на ~2 страницы A4: подсказки-извлечения
  «сигнал → первый ход» с перекосом в счёт (Т2/СЛАУ только нетривиальное), с явным протоколом чтения
  (режим самопроверки; утром тура — только рамка «Наизусть») и рукописным блоком «Мои ловушки».
  Ловушки привязаны к двойникам из тренировки, а не к нерешённым задачам корпуса.
  Здесь же живёт **разговорник фраз-объяснений** — раздел «💬 Что писать словами» (см. hard rule 11).

### Слой фраз-объяснений (авг 2026)
Ребёнок успевает написать математику, но не прозу; голый расчёт теряет балл за объяснение.
Поэтому каждая непериметровая задача в `provincial_trenirovka` и в шести `provincial_resheniya_<год>`
несёт внутри секции «✍ …на туре» блок `#### 💬 Фраза-объяснение (в начале)` (испанская фраза жирным,
русский перевод курсивом) и — для задач на счёт и перебор — закрывающий `#### 💬 Фраза в конце — полнота`;
остальная запись уходит под `#### Запись`, а абзац разбора, откуда взята фраза, помечен курсивной строкой `💬`.
**Периметрам фраз не дают — осознанное решение пользователя**, там запись говорит сама за себя.
Фразы — это не 30 отдельных текстов, а экземпляры закрытого разговорника примерно из 12 конструкций,
живущего в памятке. Бюджет ≈180 испанских символов (две рукописные строки). `grep -rn 💬` показывает весь слой.

## Корпус задач — `nandu_problemas/`

⚠ **Здесь живут две разные олимпиады, различай их по префиксу папки:**

- **Ñandú = `omn_*`** (Olimpíada Matemática Ñandú) — начальная школа, на неё и нацелен курс.
  По годам `<этап>_<год>.{pdf,md}` в `omn_regional`, `omn_zonal`, `omn_nacional`, `omn_provincial`
  (в каждом `.md` все три nivel'я Ñandú; курс использует Primer Nivel).
  Плюс `historico/*_N1.md` — многолетние компиляции Nivel 1, используются как ключи ответов.
- **OMA = `oma/`** (Olimpíada Matemática Argentina) — **отдельная, более трудная олимпиада средней школы**,
  возможный следующий шаг после Ñandú. Ни один материал курса на неё не нацелен;
  роадмап-мост, который был нацелен, удалён (см. `27-28/tinkov/README.md`).
  `oma/oma_<этап>_<год>.pdf` за 2021–2025 (этапы inter/zonal/regional/nacional; в каждом PDF Primer/Segundo/Tercer Nivel).
  Скачано с oma.org.ar по `oma_index.json`.

⚠ **`nandu_problemas/2025/` — это НЕ Ñandú**: все шесть файлов `2025_*_N1.*` — это OMA secundaria 2025
(скачаны до появления папки `oma/`; теперь они есть и там, помеченные правильно).
Настоящие условия Ñandú 2025 лежат в компиляциях `historico/*_N1.md`, раздел «Año 2025».

Артефакты скачивания и разбора: `download.sh` (загрузка PDF через gdown; сначала `source venv/bin/activate`),
`oma_index.json`, `oma_page.html`, `enunciados.js`, `zonal_list.txt` — всё производное от www.oma.org.ar.
В `venv/` стоит инструментарий извлечения PDF (pypdf, pymupdf, pdfplumber), используется однострочниками
и скриптами `python3` для превращения PDF в `.md`.

## Печать материалов

`build_pdf.py` превращает любой `.md` курса в готовый к печати `<name>_print.pdf`:
markdown → HTML → headless Chrome (страницы A5) → две A5 на альбомный A4, с номерами страниц и линией реза.
Запуск: `venv/bin/python3 build_pdf.py <files.md>` (нужны `markdown` + `pymupdf` из venv и Google Chrome).
Печатать в масштабе 100%, без «2 страницы на лист» в диалоге принтера.
Правила пагинации (глава/блок не рвутся, таблицы и врезки неразрывны, заголовок не остаётся сиротой)
лежат в CSS внутри скрипта — держать их общими для всего курса, не подгонять под один документ.
Слэш-команда `/pdf` (`.claude/commands/pdf.md`) оборачивает всё это, включая визуальную проверку страниц.
PDF собирают только для части файлов — **никогда не собирай PDF для всего репозитория без просьбы**.
